# ⚡ X-ui-ali

پنل مدیریت کانفیگ VPN شخصی، مبتنی بر **Xray-core** (پروتکل‌های VLESS / VMess / Trojan روی WebSocket)،
با یک ظاهر تازه، شیشه‌ای و کاملاً اختصاصی (Aurora Glass) — نه کپی هیچ پنل دیگری.

ساخته‌شده برای **نصب فوق‌العاده ساده روی Railway**: فورک کنید، دیپلوی کنید، یک دامنه بسازید، تمام!
از همان لحظه اول یک پنل کامل با ساب گرافیکی، QR Code، مدیریت کاربران و... در اختیار دارید.

---

## ✨ چرا X-ui-ali؟

- 🎨 **پنل حرفه‌ای و گرافیکی** — گیج‌های زنده CPU/RAM/دیسک، نمودار مصرف ترافیک روزانه، کارت‌های آماری، فید فعالیت
  زنده و دکمه‌های اکشن سریع، همه با تم اختصاصی شیشه‌ای تیره (Aurora Glass) — کاملاً متفاوت با پنل‌های مشابه
- 🏷️ **ریمارک = دقیقاً همان نامی که شما وارد می‌کنید** — هیچ پسوند یا برندی به کانفیگ‌ها اضافه نمی‌شود
- 🚀 نصب با **Fork + Deploy** روی Railway، بدون تنظیم دستی سرور
- 🖥️ اسکریپت‌های آماده نصب: `install.sh` (نصب روی VPS با Docker) و `install_railway.sh` (نصب خودکار روی Railway از طریق CLI)
- ⚡ معماری **تک‌پورت** — پنل و ترافیک VPN هر دو از یک پورت Railway رد می‌شوند
- 🔗 پروتکل‌های **VLESS، VMess، Trojan** روی WebSocket + TLS، با امکان **خاموش/روشن سراسری هر پروتکل**
- 📱 **صفحه اشتراک گرافیکی خفن** (تکی و گروهی) با هدر گرادیانی، QR Code برای هر کانفیگ، نوار مصرف ترافیک و دکمه‌های Deep Link برای بازکردن مستقیم در اپ‌ها
- 👤 ساخت/ویرایش/حذف کاربر با چند کلیک یا حتی یک کلیک («کاربر سریع»)، بدون نوشتن کانفیگ
- 📦 **گروه‌های اشتراک** — چند کاربر را در یک لینک ساب واحد ترکیب کنید (مثلاً برای بسته‌های خانوادگی/چندسرویسه)
- 🧑‍🤝‍🧑 **چند-ادمینی** — یک مالک (Owner) پنل می‌تواند ادمین‌های دیگر با دسترسی محدود اضافه کند
- 🗓️ دو استراتژی انقضا برای هر کاربر: **تاریخ ثابت** یا **شروع شمارش از اولین اتصال کاربر**
- 📊 محدودیت ترافیک (GB) و انقضا با غیرفعال‌سازی خودکار + **نمودار مصرف روزانه**
- 🕵️ **گزارش فعالیت (Activity Log)** برای تمام اکشن‌های مهم پنل
- 🖥️ **آمار زنده سرور** (CPU/RAM/دیسک/Uptime) روی داشبورد، بدون هیچ dependency اضافه
- 💾 **پشتیبان‌گیری و بازیابی کامل** پنل با یک فایل JSON (فقط برای مالک)
- 💾 ذخیره‌سازی دائمی با Volume — چیزی با ری‌استارت از بین نمی‌رود
- 🧱 بدون هیچ dependency کامپایلی — بیلد سریع، پایدار و تست‌شده end-to-end

> ⚠️ به‌خاطر معماری edge روی Railway فقط پروتکل‌های مبتنی بر WebSocket پشتیبانی می‌شوند
> (نه gRPC/UDP/WireGuard) — این محدودیت خودِ Railway است، نه پنل.

### ❌ چه چیزهایی عمداً پیاده‌سازی نشده‌اند (و چرا)

برای اینکه هیچ ویژگی «ادعایی و تست‌نشده» در پنل نباشد، این موارد آگاهانه کنار گذاشته شده‌اند چون
با معماری تک‌پورت Xray-core روی Railway به‌شکل قابل‌اعتماد قابل تست/پیاده‌سازی نیستند:

- 🔒 محدودیت تعداد IP هم‌زمان (Concurrent-IP limit)
- 📱 قفل دستگاه / HWID Lock
- 🐢 محدودیت سرعت اختصاصی هر کاربر (Per-user speed limit)
- 🔌 پورت اختصاصی برای هر کاربر (چون همه از یک پورت واحد Railway عبور می‌کنند)

به‌جای این‌ها، ارزش مشابه از طریق چند-ادمینی، گروه‌های اشتراک، گزارش فعالیت، آمار زنده سرور، نمودار
ترافیک و پشتیبان‌گیری کامل ارائه شده — ویژگی‌هایی که واقعاً تست شده و روی این معماری قابل اعتمادند.

## 🖼️ درباره «ریمارک» کانفیگ‌ها

وقتی از پنل یک کاربر جدید می‌سازید، همان **نام کاربری‌ای که تایپ می‌کنید** عیناً به‌عنوان
ریمارک (نام نمایشی) در همه کانفیگ‌های VLESS/VMess/Trojan و صفحه ساب گرافیکی همان کاربر ظاهر می‌شود —
بدون هیچ پسوند، پیشوند یا برند اضافه. اگر بعداً نام کاربری را ویرایش کنید (از صفحه جزئیات کاربر)، ریمارک
همه لینک‌ها هم بلافاصله به‌روزرسانی می‌شود.

## 🧠 معماری خلاصه

```
کلاینت (v2rayNG/...)
      │  HTTPS/WSS روی پورت 443
      ▼
  Railway Edge (TLS Termination)
      │  HTTP ساده + Upgrade: websocket
      ▼
   Node.js  (یک پورت واحد $PORT)
      ├── /            پنل مدیریت (وب)
      ├── /api/*        REST API پنل
      ├── /sub/:token    ساب استاندارد (base64)
      ├── /s/:token      ساب گرافیکی (QR + هدر گرادیانی)
      └── /<مسیرهای تصادفی>  →  پراکسی خام WebSocket → Xray-core (127.0.0.1)
                                     ├─ vless-in  (127.0.0.1:20001)
                                     ├─ vmess-in  (127.0.0.1:20002)
                                     └─ trojan-in (127.0.0.1:20003)
```

## 🧩 راهنمای ویژگی‌های جدید

### گروه‌های اشتراک (📦 گروه‌ها)
از منوی «گروه‌ها» چند کاربر را انتخاب و در یک گروه قرار دهید؛ یک لینک ساب واحد (`/gsub/:token`) و یک
صفحه گرافیکی گروهی (`/gs/:token`) ساخته می‌شود که کانفیگ‌های همه اعضا را یکجا نمایش می‌دهد — مناسب
برای فروش بسته‌های چند-سرویسه یا چند-دستگاهی زیر یک لینک.

### چند-ادمینی (🛡️ ادمین‌ها)
اولین حسابی که در Setup می‌سازید نقش **Owner (مالک)** می‌گیرد. مالک از صفحه «ادمین‌ها» می‌تواند
ادمین‌های دیگر اضافه/حذف کند. ادمین‌های عادی به همه‌چیز جز صفحه ادمین‌ها و پشتیبان‌گیری دسترسی دارند.

### دو استراتژی انقضا برای هر کاربر
- **تاریخ ثابت**: مثل همیشه، یک تاریخ مشخص انتخاب می‌کنید.
- **شروع از اولین اتصال کاربر**: تاریخ انقضا شمرده نمی‌شود تا کاربر برای اولین بار واقعاً وصل شود؛
  از همان لحظه، تعداد روزی که مشخص کرده‌اید شمارش معکوس می‌شود. مناسب برای فروش بسته‌هایی که
  مشتری هر وقت خودش خواست فعال‌شان می‌کند.

### آمار زنده سرور و نمودار ترافیک
داشبورد هر ۵ ثانیه آمار CPU/RAM/دیسک را به‌روزرسانی می‌کند (بدون رفرش صفحه) و نموداری از مجموع
مصرف ترافیک ۱۴ روز اخیر نمایش می‌دهد.

### گزارش فعالیت (⏱️ فعالیت‌ها)
هر اکشن مهم (ورود، ساخت/ویرایش/حذف کاربر یا گروه، تغییر تنظیمات، ری‌استارت Xray و…) با زمان و نام
ادمین انجام‌دهنده ثبت می‌شود.

### پشتیبان‌گیری و بازیابی
از صفحه تنظیمات (فقط مالک) می‌توانید کل وضعیت پنل (کاربران، گروه‌ها، ادمین‌ها، تنظیمات) را به‌صورت
یک فایل JSON دانلود یا از یک فایل قبلی بازیابی کنید — مفید برای مهاجرت بین سرویس‌ها یا بکاپ دوره‌ای.

### خاموش/روشن سراسری هر پروتکل
از تنظیمات می‌توانید VLESS/VMess/Trojan را کلاً خاموش کنید (مثلاً اگر یکی از آن‌ها در شبکه‌ای
فیلتر شد)، بدون این‌که لینک‌های ساب کاربران نیاز به تغییر داشته باشند.

## 🚀 روش ۱: نصب روی Railway از طریق گیت‌هاب (پیشنهادی و ساده‌ترین)

### ۱. Fork / آپلود ریپازیتوری
پروژه را طبق بخش بالا در گیت‌هاب خودتان قرار دهید (یا اگر ریپازیتوری آماده‌ای دارید، فورک کنید).

### ۲. ساخت پروژه در Railway
1. وارد [railway.com](https://railway.com) شوید و با گیت‌هاب لاگین کنید.
2. **New Project → Deploy from GitHub repo** را بزنید.
3. ریپازیتوری `x-ui-ali` را انتخاب کنید.
4. Railway به‌صورت خودکار `Dockerfile` و `railway.json` را تشخیص داده و بیلد را شروع می‌کند
   (دانلود Xray-core و نصب پکیج‌ها، حدود ۱ تا ۳ دقیقه).

### ۳. ساخت Volume دائمی (خیلی مهم)
بدون این مرحله، با هر ری‌استارت/دیپلوی، کاربران و تنظیمات پاک می‌شوند.
1. روی سرویس → **Settings → Volumes → New Volume**.
2. مسیر Mount را دقیقاً `/data` وارد کنید.

### ۴. ساخت دامنه عمومی
1. **Settings → Networking → Generate Domain**.
2. اگر پورت خواست، مقدار **8080** را بدهید.
3. دامنه‌ای شبیه `xxxx.up.railway.app` ساخته می‌شود.

### ۵. ساخت حساب مدیر
به آدرس دامنه بروید؛ چون اولین بار است، به‌طور خودکار به صفحه **Setup** می‌روید و یک نام‌کاربری/رمز برای خودتان می‌سازید.

### ۶. ساخت اولین کاربر
از منو → **کاربران → + کاربر جدید**. نامی که تایپ می‌کنید، همان ریمارک کانفیگ‌هایش خواهد بود.
سپس از صفحه کاربر، لینک **صفحه گرافیکی اشتراک** را باز کنید یا QR هر کانفیگ را اسکن کنید.

## 🚀 روش ۲: نصب خودکار روی Railway با اسکریپت (`install_railway.sh`)

اگر ترجیح می‌دهید بدون گیت‌هاب و مستقیماً از روی سیستم خودتان دیپلوی کنید:

```bash
chmod +x install_railway.sh
./install_railway.sh
```

این اسکریپت به‌ترتیب:
1. در صورت نبود، **Railway CLI** را نصب می‌کند.
2. شما را برای ورود به حساب Railway راهنمایی می‌کند (`railway login`).
3. یک پروژه جدید می‌سازد (`railway init`).
4. پروژه را دیپلوی می‌کند (`railway up`).
5. یک **Volume** روی مسیر `/data` می‌سازد.
6. یک **دامنه عمومی** روی پورت 8080 می‌سازد.

در پایان، آدرس نهایی را با `railway domain list` می‌بینید. همان آدرس را باز کنید و حساب مدیر را بسازید.

اگر Railway نمی‌خواهید و سرور لینوکسی خودتان را دارید:

```bash
git clone https://github.com/USERNAME/x-ui-ali.git
```

این اسکریپت Docker را (در صورت نبود) نصب می‌کند، ایمیج را می‌سازد، یک Volume دائمی می‌سازد
و کانتینر را با پورت دلخواه شما اجرا می‌کند. در پایان آدرس پنل را نمایش می‌دهد.

## ⚙️ متغیرهای محیطی (Environment Variables)

همه اختیاری هستند — پنل بدون تنظیم هیچ‌کدام هم کار می‌کند.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8080` | پورتی که پنل روی آن گوش می‌دهد |
| `DATA_DIR` | `/data` | مسیر ذخیره‌سازی دائمی (باید یک Volume به همین مسیر وصل شود) |
| `JWT_SECRET` | تصادفی و خودکار | کلید امضای نشست ادمین؛ اگر ست نکنید خودش ساخته و ذخیره می‌شود |
| `PUBLIC_DOMAIN` | از `RAILWAY_PUBLIC_DOMAIN` | برای override دستی دامنه (مثلاً دامنه اختصاصی) |
| `XRAY_API_PORT` | `10085` | پورت داخلی API آمار Xray (فقط 127.0.0.1) |
| `XRAY_INBOUND_BASE_PORT` | `20000` | پایه پورت‌های داخلی inboundهای Xray |

## 🖥️ اجرای محلی (اختیاری، برای تست/توسعه)

```bash
git clone https://github.com/USERNAME/x-ui-ali.git
cd x-ui-ali
npm install
mkdir -p bin
curl -L -o /tmp/xray.zip https://github.com/XTLS/Xray-core/releases/download/v26.3.27/Xray-linux-64.zip
unzip -o /tmp/xray.zip -d bin xray && chmod +x bin/xray
DATA_DIR=./data PORT=3000 XRAY_BIN=./bin/xray npm start
```

سپس `http://localhost:3000` را باز کنید.

## 🔐 نکات امنیتی

- رمز عبور ادمین را قوی انتخاب کنید و هر چند وقت از صفحه تنظیمات تغییر دهید.
- لینک **صفحه گرافیکی اشتراک** (`/s/:token`) را فقط با همان کاربر به اشتراک بگذارید.
- اگر یک کاربر نشت پیدا کرد، از دکمه «ساخت مجدد UUID / لینک ساب» در صفحه همان کاربر استفاده کنید.
- حتماً یک Volume روی `/data` بسازید — در غیر این‌صورت با هر دیپلوی، همه‌چیز از نو ساخته می‌شود.

| کلاینت وصل نمی‌شود ولی پنل بالاست | در لینک کانفیگ باید `security=tls` و پورت `443` باشد (نه پورت داخلی) |
| می‌خواهم لاگ Xray را ببینم | صفحه تنظیمات → «وضعیت هسته Xray» |
| اسکریپت `install_railway.sh` روی ساخت Volume/دامنه خطا داد | از داشبورد وب Railway دستی انجام دهید (Settings → Volumes / Networking) |
